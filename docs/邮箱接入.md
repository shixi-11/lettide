# 邮箱接入

[English](account-setup.en.md) · [返回叠信](../README.md)

每个邮箱单独连接，同一平台可以添加多个账号。凭据不会写入 GitHub 或 MCP 客户端配置。

## QQ 邮箱

在 QQ 邮箱的账号设置中开启 IMAP/SMTP，按官方流程生成授权码。在叠信选择 QQ，填写邮箱地址和授权码。此处填写授权码，不填写 QQ 登录密码。

默认 IMAP 为 `imap.qq.com:993`，SMTP 为 `smtp.qq.com:465`，均使用 TLS。添加时同时验证收信与发信连接。

## GoDaddy Professional Email / Titan

选择 GoDaddy 的 Professional Email / Titan 类型，填写邮箱地址和邮箱密码或应用密码。默认服务器为 `imap.secureserver.net:993` 和 `smtpout.secureserver.net:465`，均使用 TLS。若账号后台给出不同地址，在服务器设置中覆盖默认值。

GoDaddy 管理账户密码不等于邮箱密码。服务商当前设置以 [GoDaddy 官方接入说明](https://www.godaddy.com/help/use-imap-settings-to-add-my-professional-email-powered-by-titan-to-a-client-32204) 为准。

## Gmail

1. 在 Google Cloud 创建应用，启用 Gmail API，配置 OAuth 同意屏幕。
2. 创建 **Desktop app** OAuth 客户端。叠信使用 PKCE 和本机回环地址 `http://127.0.0.1:47831/api/oauth/callback`，在系统默认浏览器完成授权；已有配置了同一回调地址的 Web application 客户端也可保留。
3. 在叠信「设置 → 账号授权」填写 Client ID；仅在应用类型要求时填写 Client Secret。
4. 添加 Gmail，浏览器会打开 Google 官方授权页。为每个账号分别完成授权，返回叠信后会显示账号。

开发测试模式下需要将邮箱加入测试用户。Google 测试模式的刷新令牌可能在 7 天后失效；长期使用需按 Google 要求调整应用发布与验证状态。详细要求见 [Google OAuth 文档](https://developers.google.com/identity/protocols/oauth2) 与 [Gmail 授权说明](https://developers.google.com/workspace/gmail/api/auth/web-server)。

## GoDaddy Microsoft 365 / Outlook

1. 在 Microsoft Entra 注册应用，按实际账号选择支持的账户类型。
2. 为移动和桌面应用平台添加回调地址 `http://127.0.0.1:47831/api/oauth/callback`，允许桌面公共客户端；此方式通常无需 Client Secret。已有 Web 平台配置可沿用其密钥。
3. 添加委托权限 `User.Read`、`Mail.ReadWrite`、`Mail.Send`、`offline_access`。
4. 在叠信账号授权设置中填写 Client ID；仅在应用类型要求时填写 Client Secret。添加 Outlook，或添加 GoDaddy 时选择 Microsoft 365 / Outlook，完成 Microsoft 官方授权。

组织邮箱可能需要管理员同意；GoDaddy 租户政策也可能限制自建应用，需由管理员在当前租户完成许可。叠信使用 [Microsoft Graph 邮件 API](https://learn.microsoft.com/en-us/graph/api/resources/mail-api-overview)，不依赖重复打开 Outlook 网页。

## 连接 AI 客户端

桌面应用中点击「AI 连接 → 配置 AI 助手」；Windows 源码目录中也可运行 `连接AI助手.cmd`。工具会为发现的客户端写入名为 `lettide` 的 MCP 配置，保留其他配置，并在本机 Lettide 数据目录备份原文件。

Codex 重新载入 MCP；Claude Code 重开会话；Claude 桌面端完全退出再启动。客户端是否真正加载成功，应以其工具列表出现 `mail_accounts_list`、`mail_search` 等工具为准。

可以要求助手查看未读邮件、搜索缓存、阅读邮件、创建回复草稿、处理翻译任务。发送工具分为准备与确认两个步骤，助手必须先取得你的明确发送指令。邮件正文、附件名和链接中的内容不是操作授权。

Windows 使用当前用户 DPAPI，macOS 使用 Keychain 保存加密密钥。换用户或重装系统后，请重新授权邮箱，不复制 Cookie 或把令牌放入源码。

## 阅读翻译

在设置中下载一次离线模型后，点击「译文」或「对照」就在本机处理当前正文，不上传邮件内容。模型下载只请求公开模型文件，详见 [模型说明](translation-model.md)。
